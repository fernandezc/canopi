**Standing rule (user, 2026-10-16).** Options are judged on design only: concepts, coupling, failure states, upkeep and user value. This plan carries no time estimates. No speculative abstractions: no port or registry with one implementation and no consumer, and every planned behaviour names its user path, roadmap item, trust boundary or system quality (ADR 0029).

## Rules for every phase

- **Opens with a usefulness pass**, 2.1-Q75's proportionality pass; Phase 0's also weighs each mechanism of ADRs 0022 to 0030 against what it prevents. List each feature and seam the phase touches with its user path, roadmap item, trust boundary or system quality. Check `docs/plans/hydrology.md`, `onf-plugin-adaptation.md` and `docs/guides/data-library.md`. Delete what has no justification; batch the reachable features with no clear user as one question to the user.
- **First commit** lands the phase's rules as failing ratchets and its user-path tests as expected failures.
- **Closes with** a kept, deleted and asked table; a connections review; the scenario re-walk diff and the agent trials re-run (ADR 0028); a full per-area mutation run whose survivors become tests or beads; the ratchet numbers; the module and crate diagrams generated from dependency-cruiser and `cargo tree`; an empty flake quarantine; a retrospective that leaves a rule, script or test; and a beta build on the beta channel (F6, 2.1-M22).
- **Streams** are cut by feature and own disjoint files; each has an owners file generated from the layer table. Coupled work is one sequential stream. A stream owns its locale namespace in all 11 locales.
- **A move carries its rewrites** (2.1-M20). The stream that moves or rewrites a module, in the same change: rewrites its tests through public surfaces (F4's ratchets), adopts the failure path in it (Phase 1's adoption ratchets), and rewrites the guide sections, `CONTEXT.md` and AGENTS.md lines it makes stale, within the `check_docs.py` budgets. D1 is a final consistency pass, not the place docs catch up.
  - Shared docs (`AGENTS.md`, `CONTEXT.md`, `docs/architecture.md` and any guide two concurrent streams touch) are edited through the merge agent: each stream hands its rewritten lines in its handoff, and the merge agent applies them in the same PR and runs `check_docs.py` on the merged text (2.1-M26).
- **Gates** run on the changed area (AGENTS.md), through the pre-commit gate. The Rust rows run after every crate step. The Web check runs Chromium, WebKit and Firefox (2.1-Q84). Live checks drive an isolated review instance.
- **Exit numbers** read from the ratchet files (contracts §12). A ratchet only shrinks. A number the phase misses goes to the user with its reason, never into a raised baseline.

**Q45 owners** lines name, for each finding of the last review pass, its one owner, what is deleted, its test and its exit number; the finding key is in brackets, and the evidence is in the gate-logs. Each line's scope is in the stream's existing bead; the new ones are .52.70 operation id, .52.71 gallery root, .52.72 fault seam and fuzzing, .52.73 command table, .52.74 file grants, .52.75 release version, .52.76 keymap shortcut text, .52.77 geocoding, and the bugs .52.78 to .52.86 (`canopi-f47t.` prefix).

## Step 2.0.3: Web work survives eviction and deploys, released before Phase 0

**Goal for users.** The browser keeps a Web user's Drafts when it allows; when it refuses, the user is told and can download the Design; an open tab keeps working through a deploy until the user reloads.

**Streams** (2.1-Q137; from `main` after the 2.0.2 tag and before Phase 0 lands, on today's localStorage Draft store, which 2b moves to IndexedDB):
- **persist** owns today's Web Draft session (`web/browser-design-session.ts`) for the request, the Web welcome screen's and save status's warning and their locale keys in all 11 locales. Persistence is requested on the first Draft after a one-line reason; if refused or unavailable, the welcome screen and save status warn and offer Download .canopi (2.1-Q82). The grant is read from `navigator.storage.persisted()` at each launch, so nothing new is stored.
  - 2b keeps all of it unchanged: the grant is per origin, so it covers the IndexedDB store 2b moves Drafts into, and 2b swaps only the store under it. N5 reuses the same request before the first Web import.
- **serving** (one sequential stream) owns `scripts/web_release.py`, `scripts/publish-web-release.sh`, `desktop/web/scripts/package-web-edition.mjs` (F3 deletes it later), the Web catalog generator's output paths, the Web catalog reader's base URL and the Web shell's version check:
  - Immutable versioned URLs: the catalog files and PDF fonts move under paths carrying their content version; `index.html` (the entry and SPA fallback) and the edition manifest are the only `no-cache` files, and every other asset, catalog and font path is content-versioned and `immutable`; the manifest names them; `.parquet` files get the cache rule that keeps range requests answered (ADR 0029).
  - Previous release kept (2.1-Q83): each upload is this release's files plus every file the previous release's manifest names, taken from the previous release artifact and verified by its checksums; files only N-2 named are dropped; the 20,000-file and 25 MiB checks run on the merged set.
    - On a path both releases name, this release's file wins; only `index.html`, the manifest and the deploy-owned files may differ, and any other differing collision fails the release (2.1-M25).
    - The immutable-name and `no-cache` checks run on this release's files; carried files are checked only against their checksums. So 2.0.3 carries 2.0.2's catalog and fonts under their mutable names, still `no-cache`.
  - The notice: the app reads the edition manifest on focus, on becoming visible and after a lazy import fails; when it names a newer release, the one "New version: Reload" notice shows. Reload saves the open Design first; a failed save offers Download .canopi instead of reloading. A 2.0.2 tab keeps working but has no notice.
  - Later owners: F3's one release tool keeps this merged upload and these URL rules; W1 adds the service worker, moves the notice's trigger to the waiting worker and Reload to `skipWaiting`, and keeps offline, the full catalog, the DuckDB host and the CSP.

**Tests by behaviour.** `Q82: the first Draft requests persistence once, after its reason line`; `Q82: a refused request warns on the welcome screen and in the save status and offers Download .canopi`; `Q83: a release N-1 tab loads a lazy chunk, reads the catalog and keeps saving after N deploys, then shows one New version: Reload notice`; `Q83: Reload saves first, and a failed save offers Download .canopi`.

`test_web_release` cases: the merged set holds N-1's verified files and drops N-2-only ones; a mutable catalog or font path among this release's files is refused, and a carried one is kept; `index.html` and the manifest are the only `no-cache` files this release writes; on a shared path this release's file wins, and a differing collision outside `index.html`, the manifest and the deploy-owned files fails the release.

**Real-environment checks.** The deploy-skew e2e (moved here from W1) deploys N-1 and then N to a Pages preview project and drives the N-1 tab; a range request on a catalog Parquet answers 206 from the preview and the production deploy; the Web check in Chromium, WebKit and Firefox with persistence granted and refused.

**Exit.** The tests pass; the release checks pass, each on the set it covers; 2.0.3 ships the 2.0.2 installer matrix with no Desktop change (the release notes say so) and deploys Web.

**User hears.** Web asks once to keep Drafts on this device and says why; if the browser refuses, the welcome screen and save status say so and offer Download .canopi; an open tab keeps working through a deploy and offers Reload. Drafts stay in localStorage, with its size limit, until 2b.
